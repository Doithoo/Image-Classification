## 1. The data flow at a glance

```
GitHub Release (garbage-classification.tar.gz)
        │  scripts/download_data.py  (SHA-256 verified + extract)
        ▼
data/raw/  (one folder per class)
        │  garbage prepare-data  (stratified split seed=666 + bad/duplicate checks)
        ▼
data/manifests/{train,valid,test}.csv   ← portable manifests (relative paths)
        │  garbage train  (reads manifest + transforms)
        ▼
artifacts/<run>/  (config.yaml + metrics.csv + best.pt + last.pt)
        │  garbage evaluate / predict / export-onnx / explain
        ▼
test metrics / single-image prediction / ONNX model / Grad-CAM heatmap
```

## 2. Why CSV manifests instead of walking the folders

- **Portable**: a manifest stores relative paths (forward slashes), so it works
  on any machine and from any working directory.
- **Reproducible**: the manifest is generated by a stratified split with a fixed
  seed (666) and records `source.yaml` (data root + class table + checksum).
  Same data + same manifest = the same experiment.

## 3. What happens inside one training epoch

```
for epoch in range(epochs):
    for batch in train_loader:
        images, labels = batch
        if mixup/cutmix enabled:  images, soft_labels = mixup(images, labels)
        outputs = model(images)
        loss = soft_cross_entropy(outputs, soft_labels)  # or CrossEntropyLoss
        loss.backward(); optimizer.step()
    lr_scheduler.step()          # warmup → cosine
    if ema: ema.update(model)    # shadow weights
    evaluate on validation → log metrics.csv → update best.pt
    early stop if no improvement for `patience` epochs
```

### 3.1 Warmup (learning-rate ramp-up)
Starting with the full learning rate right away can make the network "overshoot".
Warmup climbs linearly from 1% to the target LR, then hands over to cosine
annealing. `SequentialLR` chains the two schedulers.

### 3.2 MixUp / CutMix (soft-label augmentation)
MixUp blends two whole images; CutMix replaces a rectangular region with a patch
from another image. Both mix labels by the effective image-area ratio, so the
loss must accept soft targets. See `training/mixup.py` for implementation notes.

### 3.3 EMA (exponential moving average of weights)
See the header of `training/ema.py`. Validation and best-checkpoint saving use
the shadow weights while training continues with the fast weights — the shadow
is smoother and generalizes better.

Two practical details matter when configuring EMA:
1. **The BN running_mean/var must be part of the average too**: averaging only
   weights pairs the shadow with the fast model's BN statistics; during
   fine-tuning the mismatch saturates activations and collapses predictions to a
   single class.
2. **The decay time constant is 1/(1−decay) steps**: 0.999 = 1000 steps. In a
   15-epoch run (~945 steps) the 0.999 shadow never catches up and drags results
   down. EMA is designed for long training runs.

### 3.4 The three class-imbalance strategies
`configs/imbalance_*.yaml` provides three comparable setups:
- `none`: plain CE loss (baseline; the rare class gets sacrificed)
- `inverse`: loss weighted by inverse class frequency (`training/weights.py`)
- `weighted`: oversample rare classes at sampling time (`WeightedRandomSampler`)

Evaluation always reports `balanced_accuracy` / `macro_f1` instead of plain
accuracy, because accuracy is dominated by the majority class.

## 4. Why checkpoints are self-contained

`training/checkpoint.py` saves: weights + optimizer/scheduler state + class map +
preprocessing stats + the full config + git revision + RNG state.

**Payoff**: `garbage predict --checkpoint xxx.pt` needs no manual class names,
normalization statistics or model name — everything is restored from the
checkpoint, so train/inference configuration cannot drift. Full experiment
reproduction additionally needs the exact manifest, dataset quality-patch
version and dependency lock.

## 5. Why evaluation reports so many metrics

The test set has 256 images and `trash` only 14. Judged by accuracy alone, a
model that always guesses `paper` still scores 23% — so `evaluate` also outputs
balanced accuracy, macro/weighted F1, per-class precision/recall/F1, the
confusion matrix, plus `predictions.csv` / `errors.csv` (a list of
misclassifications for manual error analysis).

## 5.5 Grad-CAM & TTA (inference-time tools)

- **Grad-CAM** (`garbage explain`): take the feature map of the last conv layer,
  weight each channel by the class-score gradient, and sum to get a heatmap of
  "which pixels support this decision". Use it for error analysis — when the
  model errs, check whether it looked at the wrong region. Theory in
  `inference/gradcam.py` header.
- **TTA** (`evaluate --tta` / `predict --tta`): run the input once more
  horizontally flipped and average the two softmaxes. No training involved —
  compare the metric gain with the additional inference cost (experiment 5).

## 6. Recommended learning path

1. Run one full training: `garbage train --config configs/resnet50.yaml` (start
   with `--set train.epochs 5` to see the flow quickly)
2. Plot loss curves with `scripts/plot_metrics.py` and look for
   over-/under-fitting
3. Compare the three `imbalance_*.yaml` configs and watch how trash's F1 moves
4. Turn on `mixup_alpha: 0.2` and observe: training loss rises, validation
   improves (the signature of regularization)
5. Read the headers of the four files under `training/` — each is a one-page
   note on a classic paper
